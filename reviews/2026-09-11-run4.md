## 2. Cross-cutting findings

### F1 — [blocker] Five cited census figures survive a wrong value; the whole suite stays green **[verified here]**

`0dbcc71` widened doc-truth from "figures at listed *sites*" to "a corpus figure
*anywhere*", and `TASKS.md:10733-10739` records the batch as *"any figure anywhere
is now the census … Proven red on the review's six plants plus two others."* The
commit body says it closes the case where *"a copy of the census can rot in
place"*.

It does not. `CENSUS_FIGURE_PATTERNS` (`tests/test_doc_truth.py:1922`) is a fixed
list of **eight** regex families. `tests/corpus_census.py` computes figures that
no family matches, and those figures are cited in durable documents. Planted one
at a time at the series tip, 18 plants, **5 stayed green**:

| Figure | Cited at | Outcome |
|---|---|---|
| records carrying a span id (`139`) | `CHANGELOG.md:489` | **GREEN** |
| trace-unique span ids (`135`) | `OPEN_QUESTIONS.md:1348` | **GREEN** |
| captured literals whose float repr differs (`0`) | `OPEN_QUESTIONS.md:480` | **GREEN** |
| literals carrying two values (`0`) | `OPEN_QUESTIONS.md:481` | **GREEN** |
| re-declared receipts (`0`) | `receipt_redeclared/otel_genai.notes.md:19` | **GREEN** |

Verified here on the first of these. The census prints
`records carrying a span id: 139` / `of which trace-unique …: 135`. Planting
`**139**` → `**939**` at `CHANGELOG.md:489` and running `uv run pytest
tests/test_doc_truth.py -q` gives **`47 passed`**; the sub-agent ran the full
suite on the same plant and got `2435 passed, 2 skipped`. Reverted clean.

The named-site tests pin `139`/`135` only at `OPEN_QUESTIONS.md` §12(f), so every
*copy* of those two figures rots freely — which is precisely the failure the
widening was written to end. The three zero-valued figures have no family at all.

**Why this is a blocker rather than a should-fix.** The defect is not the five
figures; it is that `TASKS.md` now asserts the class is closed. A future reader
trusts the registry and stops checking. Run 3's F1 had the same shape (a test
green by accident of container shape, advertised as a guard) and it took a cold
read to find; this one is already written into the close.

**Fix.** Either derive the patterns from `corpus_census`'s own output keys so a
new census figure cannot be cited without a family, or — better — have the census
emit every figure it computes and assert that each appearance of any of those
values in a durable document is the census value. Then correct the `TASKS.md`
sentence to say what the guard actually covers.

### F2 — [should-fix] "An `OSError` prints no bracket" is false in three durable documents, and the repo's own test asserts the opposite **[verified here]**

`audit-R16` exists to make a refusal machine-routable. It adds, in the same
commit, to `README.md:199-200`, `SPEC.md:1693` and `CHANGELOG.md:344`, the rule
that a failure the library did *not* raise **"prints no bracket: it has no code to
print"**, alongside **"the bracket is the whole of what is machine-readable on
that line"** and *"what a caller matches on is the bracketed code"*.

```
$ uv run spanweave build /nope/not-a-trace.jsonl
spanweave build: [Errno 2] No such file or directory: '/nope/not-a-trace.jsonl'
exit=1
```

Python's own `OSError.__str__` opens with `[Errno 2]`, so the line does carry a
bracket. `tests/test_cli.py:630` asserts exactly that —
`assert printed.startswith("spanweave build: [Errno 2] ")` — and
`tests/test_cli.py:287` builds the same string as a helper. So the test suite
encodes the true behaviour while three shipped documents state its negation.

This is not cosmetic: the documented matching rule, followed literally, extracts
`Errno 2` from a missing-file line and hands the caller a "code" that is not in
`SPEC.md` §3.10's table. The intent — *the CLI does not add a bracket of its own*
— is correct and worth stating; the sentence as written is a checkable claim that
is false, which is the class `audit-R6`/`audit-R13` spent two batches removing.

**Fix.** Restate as "the CLI adds no bracket of its own; a bracket on such a line
is the operating system's, and callers must not match it", and give the
machine-readable rule a positive form (the code, if any, is the bracket
immediately following `spanweave <cmd>: `, and it is one of §3.10's values).

### F3 — [should-fix] An empty parent reference to an empty span id silently loses an explicit edge, and SPEC's justifying sentence is false **[verified here]**

`audit-R10` normalizes `parent_id == ""` to "no parent" at the seam. The
placement is right (`spanweave/seam.py`, called by both adapters, no dialect
branch, `build.py` untouched) and the fixture move is honest. But `SPEC.md:893`
and `spanweave/seam.py:162-165` justify it with:

> Read as a *reference*, that empty string **names a span no input can contain**

A record whose `span_id` is `""` keeps `""` as its node identity — only a record
with *no* `span_id` gets a digest fallback. So `""` is still a valid **identity**
while having ceased to be a valid **reference**. Two-record JSONL, parent
`span_id: ""`, child `parent_id: ""`:

```
parent 7480ac3^ : edges [('', 'c', EdgeKind.PARENT, Warrant.EXPLICIT)]
HEAD            : edges []   diags ['missing_timestamp', 'missing_timestamp']
```

An `explicit` parent edge the telemetry did state is dropped, with no diagnostic —
touching invariant 2 as well as 3. The input is pathological (an exporter writing
`span_id: ""`), and the old edge was arguably as wrong as the new silence; the
finding is that the SPEC states an absolute which is checkable and wrong, and no
fixture covers the case either way.

**Fix.** Either make `""` not an identity (a record with `span_id: ""` takes the
digest fallback, so the sentence becomes true), or narrow the sentence and add the
case as a fixture with whatever diagnostic the decision warrants.

### F4 — [should-fix] The sdist citation guard cannot see the citation form it was written for **[verified here]**

`audit-R15` adds `audit_sdist`'s "ships every tracked path its own documents
cite". Its own comment says *"`reviews/` as a whole missing directory must be
visible too"*. The regex requires at least two path segments **and** a trailing
slash, so a bare top-level directory citation matches nothing:

```
CITED_PATH.findall('reviews/')              -> []
CITED_PATH.findall('.github/')              -> []
CITED_PATH.findall('fixtures/conformance/') -> ['fixtures/conformance/']
```

`CHANGELOG.md` cites `reviews/` five times and `TASKS.md` once; none matched. The
check fired on the parent only because the two review *files* are also cited by
full path. Removing `/.github` from the sdist allowlist would be caught by zero
citations.

The fix itself is sound and genuinely red-on-parent — this is about the
generalization the commit claims, not the defect it closed.

### F5 — [should-fix] The new "~238 ns" figure is attached to the wrong magnitude and contradicts SPEC's own number **[verified here]**

`aef2404` adds to `SPEC.md:1632` that `float()` *"at epoch-nanosecond magnitude
has a spacing of ~238 ns"*. Measured:

```
ulp(1.7e18)        = 256.0
ulp(1.7e9) * 1e9   = 238.4185791015625
```

238 ns is the ULP at 1.7e9 **seconds** — i.e. *after* a rescale, not at
nanosecond magnitude. `SPEC.md:162` ("spacing at 1.7e18 is **256 ns**") and
`ADAPTERS.md:175` ("at epoch-nanosecond magnitude is 256 ns") already state the
right number, so the document set now carries two different figures for the same
stated magnitude. The underlying argument survives intact — the rescale really
does collapse spans 100 ns apart — only the label is wrong.
