## BLOCKS PR

### B1 — `missing_timestamp` never names the adapter that read the record, and `e6394e2` is the commit that made that a spec violation

`e6394e2` adds the whole `adapter` paragraph to `SPEC.md` §3.7 (it is a pure
addition; the body says so: *"It was unstated before, which is why the code could
drift from its own docstring without any document disagreeing with it"*). Its
first sentence:

> `adapter` names whose records the diagnostic was made from, so a diagnostic
> about **one record** carries the adapter that read that record, and `null`
> where no adapter claimed it (§6.1).

`missing_timestamp` is record-scoped and carries `null` for a record an adapter
did claim. Measured at HEAD, one OpenInference record with no timestamps:

```
missing_timestamp    adapter=None             node='s0'
unmapped_attributes  adapter='openinference'  node='s0'
provenance: [('s0', 'openinference')]
```

Two diagnostics about the same node, whose provenance is `openinference`; one
names it and one does not. `spanweave/build.py:793-799` is the only node-scoped
`collected.add` that passes no `adapter=`; every sibling passes `by_node[node_id]`.

The protocol bar is *"spec changed in the same commit where behaviour changed"*,
and the point of changing it is that the document and the code agree. This
commit newly states a rule its own module breaks in the most commonly emitted
record-scoped diagnostic in the library.

**Registry sentence:** `missing_timestamp` names the adapter that read the record
it is about, as every other record-scoped diagnostic does.

### B2 — a whole-input diagnostic still names one adapter when a record was dropped before any adapter could read it

The same §3.7 paragraph governs the whole-input case with *"names an adapter only
when a single adapter read **every** record"*. Measured at HEAD, a two-line file —
line 1 an OpenInference span with no trace id, line 2 unparseable JSON:

```
malformed_record     adapter=None             node=None
missing_trace_id     adapter='openinference'  node=None
```

`openinference` did not read every record; one was skipped at the read stage
(`spanweave/read.py:288-296`) and never reached the seam, so it is absent from
`producers` and `_sole_contributor` (`spanweave/build.py:194`, `:256-259`) cannot
see that it existed. The message then asserts that no record in this input
reported a trace id while one record's contents are unknown.

This is the identical false-attribution the commit exists to end, one layer up:
the fix closed the *unclaimed* hole and left the *never-read* one. The two `null`
clauses in the spec sentence name mixed inputs and unclaimed records, so a
generous reading lets the letter survive; the governing clause — "read every
record" — does not.

**Registry sentence:** a whole-input diagnostic names no adapter when any record
in the input was skipped before an adapter could read it.
