**S8.2 [OPEN THREAD — regression] A consumer annotation holding an integer of


serialization*) and the `check_serializable` docstring.

Why this is not in the blocking bin:
- There is no traceback. The refusal is a documented, coded one.
- Invariant 2 governs input records, not consumer annotations.
- Determinism holds: the same bytes come out under every setting.

Why it heads the open list: S8 created a written-but-unreadable graph where
the parent refused up front.

> *TASKS.md:* `annotate.check_serializable` must refuse an integer longer than
> `jsoncodec.DIGIT_LIMIT`, because since S8 the library writes one that its own
> reader then refuses, breaking SPEC's annotation round-trip promise (run-6
> review S8.2).

**S8.3 [OPEN THREAD] Choosing the marker is quadratic under a lowered limit.**
`_unused_marker` rescans every string once per attempt. Build time for one
record whose string holds K consecutive markers, plus a 700-digit int:

| K | limit unset | `PYTHONINTMAXSTRDIGITS=640` |
|---|---|---|
| 2000 | 0.10 s | 0.13 s |
| 8000 | 0.10 s | 0.73 s |
| 32000 (0.95 MB line) | 0.12 s | 7.94 s |

Output is identical across all six combinations (`fea1987c…`). The slow path
exists only on a host that has lowered its own limit.

> *TASKS.md:* `jsoncodec._unused_marker` costs attempts × total string length,
> so untrusted input can force quadratic time under a lowered
> `PYTHONINTMAXSTRDIGITS`; choose the marker in one scan (for example, the
> highest attempt seen + 1).

**S8.4 [OPEN THREAD] An integer dict key is still subject to the interpreter's
setting, and its refusal is misworded.** Reproduced at HEAD:
`serialize.canonical_bytes({10**700: 1})` gives 708 bytes with the setting
unset and with `=0`. Under `=640` it gives `GraphNotSerializableError: … a
value refers back to itself (Exceeds the limit (640 digits) …`: the wrong
cause, and a setting-dependent acceptance. `JsonValue` keys are typed `str`,
so this is outside the typed contract, which is why it is not blocking.

> *TASKS.md:* `jsoncodec.encode` leaves integer dict keys to the interpreter's
> limit and `serialize` reports that failure as a cycle; refuse non-`str` keys
> in `check_serializable` and word the error for what it is.

> *TASKS.md:* The retired-figure check's sentence split misses `.)` and `."`
