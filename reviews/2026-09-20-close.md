## Findings

### blocks PR

**F1 — `spanweave inspect` still tracebacks on a lone surrogate, on a file
`spanweave build` wrote.** Reproduced independently by the orchestrator as well as by
the reviewer, on 3.12 and 3.14:

```
$ spanweave build t.jsonl -o g.json     ->  wrote g.json        rc=0
$ spanweave validate g.json             ->  g.json: valid       rc=0
$ spanweave inspect t.jsonl
  File "spanweave/cli.py", line 247, in _do_inspect
    print(line)
UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' in position 7: surrogates not allowed
                                        rc=1
```

`spanweave/cli.py:247` (`print(line)`) over the line built at `spanweave/cli.py:304`
(`f"trace: {document.get('trace_id')…}"`); position 7 is past the `trace: ` prefix. It
fails the same way on the **graph file `build` produced**, which `validate` calls
`valid`. `sys.stdout.errors` is `strict` both to a tty and to a pipe, so this is the
default environment, not an artifact.

The commit's subject — *"a lone surrogate is written as its JSON escape, **so nothing
about it can raise**"* — and the body's *"no `.encode` anywhere in it can raise on input
it accepted"* are false as stated. They survive only on the technicality that this is
`print`'s implicit encode rather than a literal `.encode(` call. The **honesty**
regression is new even though the crash is not: on the parent nothing worked, so nothing
was claimed; on HEAD two commands succeed and a third on the same bytes is an
interpreter traceback. Two defensible resolutions — escape (or `errors="backslashreplace"`)
at the CLI's text sink, or narrow the subject and the docstring to the encoder and
register the CLI as a thread. Either way **the sentence and the behaviour must be made
to agree before merge.**

### open thread

**F2 — `SPEC.md` §3.6's non-injectivity example is wrong for the half it names.**
*"a `\uD800` code point and the six literal characters `\ud800` give one digest"* —
measured, they do **not** give one record digest, and by construction never can, because
the escape runs after `json.dumps` has doubled the backslash. They give one rule-2/rule-3
**id material** (`spanweave/ids.py:90`). In a paragraph whose own standard is *"The
formula is exact, because a reimplementation has to land on the same id"*, this is a
sentence a reimplementer would get wrong. It over-discloses rather than under-discloses,
so nothing unsafe follows.

**F3 — the boundedness clause in the same sentence holds only for the half that can
collide.** *"two records that land on one node id are refused rather than merged"* is
true and was triggered (`DuplicateNodeIdError`, `spanweave/ids.py:159-182`). But the
sentence is attached to a *digest* collision, and a digest collision would never reach
that refusal: `spanweave/read.py:165-171` **drops** the second record and reports
`duplicate_record` with the message *"they are the same record"*. Were F2's digest half
true, the stated bound would be the wrong bound and the outcome a silent merge with a
false diagnostic. It is moot only because F2 is false. Minor mis-citation alongside: the
refusal is the *"Id collisions within a trace are a hard error"* rule, not *"rule 3's
collision rule"*.

**F4 — `SPEC.md` §8's "within three levels of the encoder's ceiling" is exact only on
3.12.** Three is the structural wrapping (`annotations` → entry → `value`) and is correct
*as structure*. As a prediction of how many depths near the ceiling get refused, the
measured parent gap is **3 on 3.12 and 2 on 3.14** — 3.14's encoder checks the C stack
pointer rather than counting frames. The fix is right on both (gap 0 each), so this is
wording, not behaviour; but the repo's own bar (`CONTRIBUTING.md`, "no test green because
of a choice it made about its own fixture") is the reason to say "the levels the document
wraps the value in" rather than a number that reads as an interpreter fact.

**F5 — C2 resolves T1 opposite to the registry sentence written for it.**
`reviews/2026-09-20-qodo.md` T1 says *"an annotation holding a lone surrogate is
**refused** at annotate time, and a graph that holds one is refused by `dumps` as a named
`GraphNotSerializableError`."* The commit **accepts and writes** it instead, and argues
the case well (*"refusing it would have been the mirror error"*, `SPEC.md` §8). The
commit's choice is the right one. Flagged only because the registry sentence is the
artifact a later reader will grep, and it now records a decision that was deliberately
not taken.

reasoning — an identical copy *was* read, so nothing about its contents is unknown —

closes it. The behaviour is right and pinned by
`tests/test_read.py::test_the_stream_counts_what_never_became_a_record`.
